<DocVariant name="heroui">
The device-authorization plugin adds the browser half of Better Auth's device authorization flow. A user enters the short code shown by a CLI, TV, or another limited-input device, signs in if needed, then approves or denies access.

It contributes:

- A `<DeviceAuthorization />` view at `/auth/device`
- Code verification with the `user_code` query parameter prefilled when present
- Sign-in redirection that preserves the pending code
- Approve and deny confirmation states
- `useVerifyDeviceCode`, `useApproveDevice`, and `useDenyDevice` mutation hooks
</DocVariant>

### Allow the new auth path

Include the plugin's path in the route that renders `<Auth />`. Keep this path aligned with the server's `verificationUri`:
</DocVariant>

```tsx doc-variant="heroui" title="routes/auth/$path.tsx"
import { viewPaths } from "@better-auth-ui/core"
import { Auth } from "@better-auth-ui/heroui"
import { deviceAuthorizationPlugin } from "@better-auth-ui/heroui/plugins"
import { createFileRoute, notFound } from "@tanstack/react-router"

const validAuthPathSegments = new Set([
  ...Object.values(viewPaths.auth),
  deviceAuthorizationPlugin().viewPaths.auth.deviceAuthorization
])

export const Route = createFileRoute("/auth/$path")({
  beforeLoad({ params: { path } }) {
    if (!validAuthPathSegments.has(path)) {
      throw notFound()
    }
  },
  component: AuthPage
})

function AuthPage() {
  const { path } = Route.useParams()
  return <Auth path={path} />
}
```

## Options

```ts
deviceAuthorizationPlugin({
  // Override the URL segment. Default: "device"
  path: "activate",
  // Match Better Auth's server-side userCodeLength. Default: 8
  userCodeLength: 8,
  localization: {
    approveDevice: "Allow this device?"
  }
})
```

<type-table path="packages/core/src/plugins/device-authorization/device-authorization-plugin.ts" name="DeviceAuthorizationPluginOptions" />

Keep `userCodeLength` equal to the value passed to Better Auth's server plugin. A mismatched length prevents valid codes from being submitted.

## React APIs

The view uses these React Query hooks:

- [`useVerifyDeviceCode`](/docs/react/mutations/verify-device-code) verifies and claims the submitted code for the current session.
- [`useApproveDevice`](/docs/react/mutations/approve-device) grants the requesting device access.
- [`useDenyDevice`](/docs/react/mutations/deny-device) rejects the request.
</DocVariant>

- [`denyDeviceOptions`](/docs/solid/mutations/deny-device) rejects the request.
</DocVariant>

## Sessions and revocation

<DocVariant name="heroui">
The device token creates an ordinary Better Auth session after approval. There is no separate device registry in the device-authorization plugin. Use [`<ActiveSessions />`](/docs/heroui/components/settings/security/active-sessions) to list sessions and revoke access for an approved device.
</DocVariant>

<DocVariant name="shadcn">
An approved device token creates an ordinary Better Auth session. There is no separate device registry in the Device Authorization plugin. Use [`<ActiveSessions />`](/docs/shadcn/components/settings/security/active-sessions) to list sessions and revoke access for an approved device.
</DocVariant>

<DocVariant name="zaidan">
An approved device token creates an ordinary Better Auth session. There is no separate device registry in the Device Authorization plugin. Use [`<ActiveSessions />`](/docs/zaidan/components/active-sessions) to list sessions and revoke access for an approved device.
